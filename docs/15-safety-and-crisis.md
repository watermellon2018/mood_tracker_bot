# 15. Безопасность формулировок и кризисный сценарий

Бот работает с чувствительной темой (БАР, депрессия, гипомания, суицидальные мысли). Поэтому в проекте есть несколько отдельных политик безопасности:

## 1. Нейтральные формулировки

Бот **никогда** не пишет пользователю:
- «Гипомания» (как клинический диагноз).
- «Депрессия» / «депрессивный эпизод».
- «Биполярное расстройство» / «БАР».
- «Маниакальный».

Тексты в выводе всегда нейтральные:
- «Сверхприподнятое / разогнанное состояние».
- «Сниженное / низкое настроение».
- «Это наблюдение, не диагноз».
- «При необходимости данные можно обсудить со специалистом».

См. [`bot/constants.py`](../bot/constants.py) (`MOOD_DESCRIPTIONS`, `ANXIETY_DESCRIPTIONS`, etc.) и [`bot/texts.py`](../bot/texts.py) (`Q_MOOD`, `DISCLAIMER_FOOTER`).

Внутренние коды могут быть техническими (`hypomania` как `question_code`), но в UI это становится «Подъем / гипомания» или «Признаки подъема» (см. `QUESTION_DEFINITIONS`).

## 2. DISCLAIMER_FOOTER

Каждое текстовое саммари статистики оканчивается:

```
Это наблюдение, не диагноз. При необходимости данные можно обсудить со специалистом.
```

Реализация в `stats.py::_send_report`:
```python
summary_text = stats_service.build_summary(...) + DISCLAIMER_FOOTER
```

## 3. Кризисное сообщение

Текст ([`bot/constants_questions.py::CRISIS_MESSAGE`](../bot/constants_questions.py)):

```
Если сейчас плохо и есть мысли о том, чтобы навредить себе — пожалуйста,
обратись за срочной помощью: к близкому человеку, врачу, в экстренную службу
или местную кризисную линию. Я не заменяю помощь специалиста.
```

Принципы текста:
- Без конкретных номеров (они зависят от страны и могут устаревать).
- Без обещаний помощи от бота.
- Чёткое разделение: бот ≠ специалист.

## 4. Trigger кризисного сообщения

Реализация в `bot/handlers/survey.py::optional_question_step`.

Когда пользователь выбирает крайний (5-й) вариант ответа на вопрос `suicidal_thoughts` (`SUICIDAL_HIGH_RISK_INDEX = 4`):
```python
options = [
    "Нет",                                       # 0
    "Были мимолётные мысли",                     # 1
    "Были навязчивые мысли",                     # 2
    "Думал(а) о способах",                       # 3
    "Есть риск, что могу навредить себе",        # 4 ← high-risk
]
```

В FSM:

```python
if code == "suicidal_thoughts" and choice_idx == SUICIDAL_HIGH_RISK_INDEX:
    survey["high_risk_triggered"] = True
    logger.warning("Suicidal high-risk ответ tg=%s — будет показано кризисное сообщение", ...)
```

После `_finish_survey` отдельным сообщением:

```python
if high_risk_triggered:
    await target.reply_text(CRISIS_MESSAGE)
```

То есть **поток опроса не прерывается**, пользователь видит сначала summary, потом кризисное сообщение. Это намеренно: не хочется пугать пользователя резким переключением.

## 5. Подтверждение включения `suicidal_thoughts`

В разделе настроек этот вопрос можно включить только через явное подтверждение:

1. Тап на вопрос в категории `health` → callback `qs:tgl:suicidal_thoughts`.
2. Handler перехватывает: показывает `SUICIDE_WARNING`:

```
Этот блок нужен только для самонаблюдения и не заменяет помощь специалиста.

Если вы чувствуете, что можете навредить себе, обратитесь за срочной помощью:
к близкому человеку, врачу, в экстренную службу или местную кризисную линию.
```

3. Кнопки: «✅ Включить» (`qs:suicide_confirm`) / «Отмена» (`qs:suicide_cancel`).
4. На подтверждение — `question_settings_service.set_suicidal_after_confirm(session, user_id)`.

Защита в сервисе:
```python
def set_question_enabled(session, user_id, code, is_enabled):
    if code == SUICIDAL_CODE and is_enabled:
        # Принудительный путь — выставлять только через set_suicidal_after_confirm.
        logger.warning("Попытка прямого включения suicidal_thoughts ... отказано")
        return False
    return _upsert(...)

def toggle_question(session, user_id, code):
    ...
    if code == SUICIDAL_CODE and new_value:
        return False
    ...
```

Это значит, что:
- Прямые toggle / set_question_enabled с True для `suicidal_thoughts` будут отказаны.
- **Пресеты не включают** `suicidal_thoughts` (`codes = [c for c in codes if c != SUICIDAL_CODE]`).
- Включить можно **только** через UI-flow с warning.

Выключить — обычным toggle (без подтверждения).

## 6. Безопасность данных

- Бот хранит **минимум данных**: `telegram_user_id`, TZ, ответы на вопросы.
- Никаких персональных данных (имя, телефон, email).
- Удаление пользователя в БД → CASCADE удаляет все его записи, settings, pending, custom questions.
- Содержимое комментариев пользователя **НЕ логируется** (только факт сохранения).

## 7. Безопасность ввода

- Все текстовые вводы валидируются:
  - Комментарий: ≤1000 символов.
  - Custom question text: 1..150 символов + CHECK в БД.
  - Custom text answer: 1..1000 символов.
  - HH:MM формат строго проверяется.
  - N дней частоты: 2..30.
- Защита от чужих id: `get_owned(user_id, question_id)` в custom_questions.
- CHECK-констрейнты в БД — последний рубеж.

## 8. Дисклеймер в /start и /help

`WELCOME`:

> Я не ставлю диагнозы и не заменяю врача. Я только сохраняю твои ответы и показываю динамику.
>
> Если тебе сейчас очень плохо или есть риск причинить вред себе, обратись за срочной помощью к близкому человеку, врачу или в экстренную службу.

Это — первое, что видит пользователь после регистрации.
